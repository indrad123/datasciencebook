# Chapter 39 Solutions

1. A cluster is an algorithmic group under chosen geometry. A business segment adds an owned, governed, measurable action.
2. Distributor-level annual behaviour differs from order-level weekly behaviour. The window controls maturity, seasonality, and recency.
3. They repeatedly encode the same concept and therefore give size excessive weight in distance.
4. Assign rows to $k$ centroids so the sum of squared distances within clusters is as small as possible.
5. The objective is non-convex, so different starting centroids can reach different local solutions.
6. Inertia always declines as clusters increase and becomes zero when each row can be its own cluster.
7. $(5-2)/5=0.6$.
8. Near 1 indicates strong cohesion and separation; near 0 indicates a boundary; below 0 suggests closer average proximity to another cluster.
9. Single uses closest points and can chain. Complete uses farthest points and favours compact groups. Ward minimises the increase in within-cluster variance.
10. When groups have irregular shapes and sparse observations should be labelled as noise, provided density settings are suitable.
11. Code gaps and order have no justified semantic meaning but are treated as quantitative distance.
12. Repeated seeds, bootstrap or subsample refits, adjacent windows, scaling alternatives, feature-block removal, and nearby hyperparameters are valid.
13. Numeric labels are arbitrary. Label-invariant agreement measures compare membership without assuming cluster 0 has the same name.

Define active distributors over a mature 12-month window; use reviewed order rhythm, mix, margin, service, and trend features; scale inside the reference pipeline; compare k-means, hierarchical, and suitable mixed-data methods; test silhouette, stability, size, fairness, and actionability; pilot service policies.
15. Determine whether it contains errors, outliers, strategic accounts, a genuine niche, or an operationally unusable artefact. Do not select by silhouette alone.
16. Apply the saved feature pipeline and nearest-centroid rule where appropriate, require a maximum assignment distance, label remote cases unassigned, route them to review, and version any centroid refresh.
